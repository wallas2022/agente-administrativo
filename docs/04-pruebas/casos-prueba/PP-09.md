# PP-09 — Segregación de funciones

**Versión:** 0.2.0
**Fecha:** 2026-09-30
**Relacionado con:** HU-09 / RNF-02 · docs/04-pruebas/plan-pruebas-prototipo.md · Entrega 1 · **Bloqueante para salida del piloto**

## Cambio v0.9 (decisión del responsable del proyecto)

La segregación de funciones (RN-07, "quien carga no aprueba") pasó de obligatoria a **configurable** (`SEGREGACION_APROBACION`, por defecto `false`). PP-09 ya no puede medir "0 autoaprobaciones permitidas" como umbral universal -- por diseño, con la configuración por defecto, la autoaprobación SÍ está permitida. Lo que se vuelve bloqueante para el piloto es la **trazabilidad**: toda autoaprobación debe quedar registrada, sin excepción.

## Objetivo

Verificar que:
1. Con `SEGREGACION_APROBACION=false` (por defecto), la autoaprobación está permitida en CU-01/CU-02/CU-05 y **toda** autoaprobación queda registrada en la bitácora (usuario, rol, fecha, hallazgo, marca "autoaprobado") y visible en el reporte "Ajustes autoaprobados".
2. Con `SEGREGACION_APROBACION=true`, el sistema restaura el bloqueo original (RN-07 como en v0.8).

## Precondición

Usuario con rol Revisor o Administrador que además cargó un documento con hallazgos generados (caso 1); mismo escenario con `SEGREGACION_APROBACION=true` (caso 2).

## Datos de entrada

Un documento cargado por un usuario con rol Revisor o Administrador (el único caso donde upload + decisión coinciden en la misma persona, dado que el rol Analista nunca tiene permiso de decidir, por rol, independientemente de esta configuración).

## Pasos

1. Con `SEGREGACION_APROBACION` sin definir o en `false`: decidir sobre los hallazgos con el mismo usuario que cargó. Confirmar que la acción se permite y que la bitácora (y el reporte "Ajustes autoaprobados") registran la autoaprobación con usuario, rol, fecha y hallazgo.
2. Con `SEGREGACION_APROBACION=true`: repetir el mismo intento y confirmar que el sistema bloquea la acción (403).
3. Repetir el caso 1 con un usuario Revisor distinto de quien cargó -- confirmar que se permite y que NO queda marcado "autoaprobado".

## Resultado esperado

Caso 1: la decisión se permite y queda registrada como autoaprobada. Caso 2: el sistema bloquea la decisión. Caso 3: la decisión se permite y no se marca autoaprobada.

## Umbral / métrica

**0 aprobaciones sin registro** (antes, hasta v0.8: "0 autoaprobaciones permitidas" -- umbral retirado porque ahora la autoaprobación es una configuración válida, no un defecto a prevenir).
