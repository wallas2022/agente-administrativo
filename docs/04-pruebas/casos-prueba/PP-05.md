# PP-05 — OCR de imágenes legibles

**Versión:** 0.1.0
**Fecha:** 2026-10-09
**Relacionado con:** HU-05 / RF-11 · docs/04-pruebas/plan-pruebas-prototipo.md · Entrega 2

## Objetivo

Verificar la precisión de caracteres (CER) del motor de OCR sobre imágenes y PDF escaneados legibles, incluyendo variaciones realistas (perspectiva, rotación) y que las cifras nunca se alteren.

## Precondición

Dataset de imágenes/PDF legibles con texto esperado documentado (hoja de respuestas); `tipo_revision="ocr"` implementado (CU-06, Bloques 1-3).

## Datos de entrada

Documentos del dataset con montos, fechas y siglas del glosario conocidos de antemano.

## Pasos

1. Procesar cada documento con el motor de OCR (`ocr.documentos.procesar_documento`).
2. Comparar el texto reconocido contra la hoja de respuestas (CER, Levenshtein).
3. Verificar que los montos y siglas aparecen exactos (substring), no solo "dentro de la tolerancia general de CER".
4. Para el caso rotado, verificar que el OSD detecta la rotación.

## Resultado esperado

El texto reconocido coincide con el esperado dentro del umbral de CER; las cifras nunca se alteran; la rotación se detecta y corrige.

## Umbral / métrica

CER ≤ 5 % (equivalente a ≥ 95 % de precisión de caracteres)

## Ejecutado (Bloque 4, 2026-10-09)

Dataset sintético construido para este bloque (`tests/dataset/cu-06/`, texto propio renderizado, sin datos reales): 3 imágenes legibles (render limpio, perspectiva leve, rotada 90°) + 1 PDF escaneado de 2 páginas. Medido contra Tesseract real dentro del contenedor del worker (sin mocks): **CER 0.000 en las 4 páginas**, montos y sigla "SAT" verificados exactos, rotación de 90° detectada correctamente por OSD -- cumple el umbral con margen amplio. En el camino se encontró y corrigió un bug real del deskew que degradaba imágenes ya derechas (ver detalle en [docs/04-pruebas/resultados/local-CU06.md](../resultados/local-CU06.md)).

**Limitación de esta medición**: dataset sintético y pequeño (texto renderizado por computadora, no documentos reales fotografiados/escaneados) -- un CER de 0 % aquí es el piso, no una garantía sobre documentos reales con ruido físico (manchas, impresoras de baja calidad). Ampliar con un dataset real queda pendiente, mismo riesgo R-08 que ya aplica a CU-01/CU-05.
