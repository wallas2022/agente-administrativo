# PP-06 — OCR de imágenes de baja calidad

**Versión:** 0.1.0
**Fecha:** 2026-10-09
**Relacionado con:** HU-05 · docs/04-pruebas/plan-pruebas-prototipo.md · Entrega 2 · RN-06

## Objetivo

Verificar que, ante una imagen de baja calidad (ilegible incluso para una persona), el motor de OCR informa la ilegibilidad en vez de inventar una transcripción con apariencia de resultado confiable.

## Precondición

Dataset con imágenes de baja calidad conocidas (desenfoque fuerte, bajo contraste); umbrales de confianza configurados (`OCR_PAGINA_ILEGIBLE`, Bloque 2).

## Datos de entrada

Imágenes deliberadamente degradadas: desenfoque fuerte + ruido, y texto con muy poco contraste contra el fondo.

## Pasos

1. Procesar cada imagen de baja calidad con el motor de OCR.
2. Verificar que la página se clasifica como ilegible (`ocr.calidad.es_pagina_ilegible`).
3. Verificar que no se publica ningún texto para esa página (solo el aviso).

## Resultado esperado

100 % de las imágenes de baja calidad se informan ilegibles; 0 texto inventado.

## Umbral / métrica

Informa ilegibilidad en lugar de inventar: 100 %

## Ejecutado (Bloque 4, 2026-10-09)

Dataset sintético (`tests/dataset/cu-06/baja_calidad_*.png`, 2 imágenes: desenfoque fuerte, bajo contraste). Medido contra Tesseract real dentro del contenedor del worker: **2/2 (100 %) correctamente marcadas ilegibles** (confianza media 0.0, texto vacío) -- cumple el umbral. En el camino se encontró y corrigió un bug real: sobre una imagen lo bastante degradada, el propio comando de OSD de Tesseract podía fallar con una excepción (`TesseractError`) en vez de simplemente devolver confianza baja, lo que tumbaba el análisis completo en vez de marcarlo ilegible -- corregido en `ocr.orientacion.detectar_rotacion_tesseract` (si el OSD falla, se asume "sin rotación" y se deja que la clasificación de confianza, que no depende del OSD, decida). Detalle en [docs/04-pruebas/resultados/local-CU06.md](../resultados/local-CU06.md).
